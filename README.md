# Бот КСТ — Telegram-бот студентов Красноярского строительного техникума

Бот помогает студентам:

- зарегистрироваться и указать свою группу (например, `26КАД`);
- смотреть расписание на сегодня / завтра / любой день недели с учётом
  чётности (числитель / знаменатель);
- смотреть замены из «Листа замен» сайта техникума;
- вести личные дедлайны (добавить / удалить / редактировать);
- получить ссылку на .ics-подписку для Google / Apple Calendar;
- получать уведомления о новых заменах на завтра (проверка раз в 15 минут).

## Запуск

Три способа — выбирай любой. Везде перед первым стартом нужен `.env`
(скопировать из `.env.example` и вписать `BOT_TOKEN`, `PUBLIC_BASE_URL`).

### 1. Локально (Python 3.11+)

```bash
python -m venv .venv
.venv\Scripts\Activate.ps1        # Windows; Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env            # Windows; Linux/macOS: cp .env.example .env
# вписать BOT_TOKEN и PUBLIC_BASE_URL в .env
python -m bot.main                # или: python run.py
```

### 2. Docker

```bash
docker build -t kst-bot .
docker run --env-file .env -p 8080:8080 -v ${PWD}/data:/app/data kst-bot
```

На Linux/macOS подставь `$(pwd)` вместо `${PWD}`. Том `/app/data` обязателен:
в нём живут БД SQLite, кэш источников и бэкапы.

### 3. docker-compose (только локально)

```bash
docker compose up --build
```

## Проверка Docker

Сборка и запуск контейнера (порядок важен: сначала образ, потом запуск,
затем проверка здоровья в **другом** окне терминала).

```bash
# 1. Собрать образ
docker build -t kst-bot .

# 2. Запустить (--rm — удалить контейнер после остановки)
docker run --rm --env-file .env -p 8080:8080 -v "%cd%/data:/app/data" kst-bot

# 3. В другом окне — проверить здоровье
curl http://localhost:8080/health
# ожидание: JSON со "status": "ok", "db": "ok", схемой и числом занятий

# 4. Остановить: Ctrl+C в окне с контейнером
# в логах должно быть: "shutdown signal received" → "bot stopped"
```

На Linux/macOS в шаге 2 подставь `"$(pwd)/data:/app/data"` вместо
`"%cd%/data:/app/data"`.

**Что проверить в выводе:**

- сборка проходит без ошибок; в образ не попадает `.env` (секреты) и `tests/`;
- контейнер работает от непривилегированного пользователя `app`;
- в логах старта: `web server started`, `background tasks started, count: 6`,
  `rate limiter installed`, `backup done`;
- `curl` возвращает 200; при остановке — `bot stopped` без traceback
  и без `Unclosed client session`.

**Если `docker build` падает:** чаще всего это отсутствие файла в контексте
(проверь, что `requirements.txt`, `bot/` и `run.py` не исключены
в `.dockerignore`) или недоступный `pip` — тогда повтори сборку с
`--no-cache`.

## Ручной end-to-end тест

Чек-лист для проверки живого бота в Telegram. Нужны два аккаунта: обычный
студент и админ (его `tg_id` должен быть в `ADMIN_IDS`, а `ADMIN_CHAT_ID` —
указывать на чат, где ты читаешь сообщения).

### Регистрация и расписание

1. **`/start`** → приходит приглашение ввести группу. Отправь `26КАД` →
   «✅ Группа 26КАД сохранена» → dashboard с группой, датой, чётностью
   и числом пар на сегодня.
2. **Опечатка:** отправь `/start`, затем `26КД` → бот отвечает «Группы
   26КД нет в расписании» и предлагает до 3 похожих кнопками. Нажми
   предложенную — группа сохранится.
3. **«📅 Сегодня»** → расписание на сегодня; в шапке обязательно
   «🗓 Число: DD → Чет/нечет», где чётность соответствует числу месяца.
   Если пар нет — «🎉 Пар нет».
4. **«📆 Расписание»** → жми **◀️** и **▶️**: дата меняется на день
   вперёд/назад, число и чётность **пересчитываются**. Проверь переход
   через границу месяца: например, 30.09 (Чет) → 01.10 (нечет).
5. **Замена:** найди день, где в расписании есть замена (или дождись
   обновления листа замен). У пары должна быть иконка **🔁** и строка
   «Было: …». У отменённой пары — **❌**, у самостоятельной работы — **📖**.

### Дедлайны

6. **«📝 Дедлайны»** → пустой список → «➕ Добавить» → выбери способ
   привязки:
   - «📚 По предмету» → выбери предмет своей группы;
   - «🧑‍🏫 По преподавателю» → выбери преподавателя;
   - «✏️ Произвольный» → введи название текстом.
   Затем введи задачу → «📅 Календарь» → выбери дату → дедлайн появился
   в списке с группой срочности (🔴/🟠/🟡/⚪).
7. **Удаление:** нажми «❌ <задача>» → «✅ Да, удалить» → дедлайн исчез
   из списка. Запись при этом остаётся в БД с `deleted_at` (мягкое удаление) —
   это нормально.

### Календарь (.ics)

8. **«👤 Профиль»** → «📆 Интеграция с календарём» → «📱 iPhone / iPad» →
   скопируй `webcal://`-ссылку → открой её на телефоне → подписаться.
   Для Android: в Google Calendar → «Другие календари» → «+» →
   «Создать по URL» → вставь `https://`-ссылку.
   *Важно:* по `http://localhost` подписка не заработает — нужен публичный
   HTTPS-домен (`PUBLIC_BASE_URL`).
9. **Проверка чётности в календаре:** открой два дня, где числа чётное
   и нечётное (например, 22.09 — число 22 → «Чет», 23.09 — число 23 →
   «нечет»). Предметы должны отличаться в соответствии с DOCX: в чётный
   день стоит предмет из «Чет»-строки, в нечётный — из «нечет».

### Прочее

10. **`/help`** → справка со списком возможностей и команд.
11. **«🐛 Сообщить о проблеме»** → введи текст → пользователю «🙏 Спасибо,
    передали администратору», а в `ADMIN_CHAT_ID` приходит отчёт с именем,
    `tg_id`, группой, последним экраном и версией бота.
12. **`/stats`** (админ) → отчёт: пользователи, активные за 7 дней, топ групп,
    размер БД, состояние кэшей. **От обычного аккаунта `/stats` должен
    ответить «Команда не найдена»** — админ-команды не подтверждают себя.
13. **`/broadcast`** (админ) → пришли текст → предпросмотр с числом
    получателей → «✅ Отправить» → отчёт «отправлено / ошибок /
    заблокировали бота». «↩️ Отмена» на предпросмотре ничего не отправляет.
14. **Остановка:** `Ctrl+C` в терминале → в логах `shutdown signal received`
    → `bot stopped`, процесс завершается **без traceback** и без
    `Unclosed client session`.

### Если что-то не сработало

- Проверь `ADMIN_IDS` и `ADMIN_CHAT_ID` в `.env` — без них админ-команды
  молчат, а обратная связь не уходит.
- Расписание в боте берётся из кэша: если данных нет, дождись первого
  обновления (оно идёт сразу при старте) или вызови `/reparse` (админ).
- Для .ics нужен публичный HTTPS: `PUBLIC_BASE_URL` вида
  `https://<домен>` без слэша на конце.

## Что нужно от хостинга

Привязки к конкретному провайдеру нет — владелец выбирает сам
(VPS, Amvera, Render, Railway, Docker и т.д.). Требования:

| Требование | Зачем |
|---|---|
| Python 3.11+ **или** Docker | окружение приложения |
| Персистентный том на `/app/data` | SQLite, кэш источников, бэкапы |
| env-переменные | `BOT_TOKEN`, `PUBLIC_BASE_URL`, `PORT`, `DB_PATH`, `CACHE_DIR`, `ADMIN_IDS`, `ADMIN_CHAT_ID`, `LOG_LEVEL` |
| Один открытый порт (8080) | `/health` и `/calendar/{token}.ics` |
| Публичный **HTTPS**-домен | .ics-подписка: клиенты календарей требуют https |
| Постоянный процесс | **не serverless**: нужны долгий polling и фоновые задачи |

Последний пункт важен: Vercel и Netlify не подойдут — там функции живут
секунды, а боту нужны постоянный процесс (`start_polling`) и шесть фоновых
задач (обновление расписания и замен, напоминания, рассылка, бэкапы,
проверка здоровья).

### Проверка после запуска

- `http://<хост>:8080/health` → JSON со `status: ok`, версией схемы и числом
  занятий в кэше; если БД недоступна — 503.
- `http://<хост>:8080/calendar/<токен>.ics` → файл календаря (токен выдаёт
  бот в «Профиль → Интеграция с календарём»).
- В логах: `web server started`, `background tasks started, count: 6`,
  `rate limiter installed`.
- Остановка (Ctrl+C или SIGTERM) → `shutdown signal received` → `bot stopped`,
  процесс завершается без `Unclosed client session`.

## Надёжность и эксплуатация

- **Graceful shutdown**: по SIGINT/SIGTERM задачи отменяются, HTTP-сервер
  гасится, сессия бота и соединение с БД закрываются. На Windows
  `add_signal_handler` недоступен — используется `signal.signal`.
- **Автоперезапуск polling**: сетевая ошибка не завершает процесс, повтор
  через 10 секунд. Если во время паузы пришёл сигнал остановки — выходим.
- **Rate limit**: 20 сообщений в минуту на пользователя; лишние молча
  игнорируются (без ответа «слишком часто», чтобы не подсказывать лимит).
- **Бэкапы**: раз в сутки (и сразу при старте) копия БД через SQLite backup
  API в `data/backups/bot_YYYYMMDD.db`; копии старше 7 дней удаляются.
  Именно backup API, а не копирование файла: в режиме WAL часть данных лежит
  в `-wal`, и простое копирование дало бы неполную копию.
- **Мониторинг**: раз в час проверка — падения парсера подряд, возраст кэша
  больше 24 ч, рост размера БД больше чем в 2 раза за сутки. Алерты уходят в
  `ADMIN_CHAT_ID`, повтор не чаще раза в сутки (флаги в таблице `meta`).

## Стек

Python 3.11+, aiogram 3.x, aiohttp, beautifulsoup4 + lxml, sqlite3 (чистый,
без ORM), asyncio, Docker + Amvera.

## Ключевые правила

- Даты — только ISO (`YYYY-MM-DD`), время — `Asia/Krasnoyarsk` (UTC+7).
- Чётность: **Чёт/нечет определяется числом месяца. День недели и месяц не
  влияют.** Формула: `'Чет' if d.day % 2 == 0 else 'нечет'`. Единственный
  источник правды — `week_type_for_date()` (Шаг 6).
- Все настройки — через env-переменные (см. `.env.example`); секреты не
  попадают ни в код, ни в логи, ни в git.
- Логи — JSON через `logging` (никаких `print`).

### Шаг 5 — Слой данных: скачивание источников и кэш — ЗАКРЫТ

Реализовано в `bot/services/cache_service.py`. Правила кэша соблюдены и
покрыты тестами: только последняя успешная версия; падение скачивания и
пустой результат разбора не затирают кэш; `last_successful_fetch` пишется
только при успехе; файлы источников лежат в `data/cache/` с `.meta.json`.

Параметры сети (согласованы): connect-timeout 30 с, общий таймаут 60 с,

1. Кэш хранит **только последнюю успешную версию**, история не нужна.

5. Файлы источников лежат в `data/cache/` под фиксированными именами

### Шаг 9 — .ics-сервер: подписка в календаре — ЗАКРЫТ

**Ключевое решение — почему НЕ RRULE:** чёт/нечет определяется чётностью
ЧИСЛА МЕСЯЦА, а не номером недели, поэтому `RRULE:FREQ=WEEKLY;INTERVAL=2`
даёт неверный календарь. Вместо этого генерируются конкретные `VEVENT` на
каждый день горизонта (60 дней): для каждой даты берётся её чётность и
выбираются подходящие пары.

**Прочие решения:**

- `DTSTART`/`DTEND` — с `TZID=Asia/Krasnoyarsk`, без перевода в UTC;
- `UID` = md5 от группы, даты, пары и предмета — стабилен между
  генерациями, поэтому клиент обновляет события, а не плодит дубли;
- фолдинг по 75 октетов режет по границе символа: кириллица занимает
  2 байта, разрез по байту дал бы битый символ;
- токен — `uuid4().hex`, один на пользователя; Telegram id в ссылку не
  попадает;
- при занятом порте бот сообщает `web server failed to bind` и закрывает
  уже открытые ресурсы (иначе в логах оставался `Unclosed client session`).

**Файлы:** `bot/services/ics_service.py`, `bot/web.py`,
`bot/handlers/calendar.py`, `bot/migrations.py` (миграция 4),
`bot/config.py` (константы `ICS_*`), `bot/main.py`,

  попадают полные ФИО, а не фамилии.

### Кабинет «404/1Б» — решение принято

`404/1Б` — **ОДИН** кабинет («кабинет 404, корпус 1Б»). Правило: пара
`число/число+буква` (шаблон `\d+/\d+[А-Яа-я]+`) не разбивается, потому что
первая часть — голый номер без буквы корпуса.

Пары вида `401Б/308Б`, `314Б/306Б`, `406А/405А` — это **ДВА** кабинета:
в DOCX те же места записаны через запятую (`401Б, 308Б` — 4 раза,
`314Б, 306Б` — 6 раз, `406А, 405А` — 10 раз), то есть буква корпуса стоит
в первой части и это два разных помещения.

Реализация — `bot/parsers/substitutions.py`: `CORPUS_SLASH_ROOM_RE` и
`join_corpus_rooms()`. Покрыто тестами `test_split_rooms_corpus_slash_is_one_room`
и `test_split_rooms_slash_without_spaces`.

## Имена групп

Одна группа в источниках пишется по-разному, поэтому обе стороны приводятся
к каноническому виду функцией `normalize_group_name` (`bot/parsers/groups.py`):
верхний регистр, без пробелов и дефисов, ведущая «О» → «0».

| Источник | Как записано | Канонически |
|---|---|---|
| DOCX | `26 С1`, `25 КАД`, `026 С` | `26С1`, `25КАД`, `026С` |
| HTML | `26КАД`, `25 КАД`, `026 С` | `26КАД`, `25КАД`, `026С` |

Пример «26МОСДР-1» → «26МОСДР1» (дефис удаляется). Одна и та же функция
используется в `schedule.py` и `substitutions.py` — иначе замены не нашли бы
нужные пары расписания.
